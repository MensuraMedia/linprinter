# 0.2.8 — USB link health, no fallback onto a broken link, queues by URI — 2026-10-01

## Symptom
The TR150 "appeared not connected" and "rejected jobs". LinPrinter listed only Print to PDF while the
printer was off the bus, and Print in other programs failed.

## Root causes (from this machine's logs)
1. **The USB link.** Kernel: `device descriptor read/64, error -71`, `device not accepting address`,
   `Cannot enable. Maybe the USB cable is bad?` on ports 3-3 and 3-1; the printer re-enumerated every
   5-45 s. With a new cable it held on 3-3 (0 errors in 2 min), then failed to enumerate after a power
   cycle. Not a driver: these happen before any driver binds. `usbcore.quirks=04a9:18a4:k` (LPM off)
   made no difference.
2. **A misdirected CUPS queue.** `Canon_TR150_series_USB`, a raw queue on `serial:/dev/ttyS0`, created
   2026-10-01 22:44 while the printer was off the bus, was the system default and not accepting jobs.
   LinPrinter listed it as a working P2 method: `lpstat -l -e` (read first) announced the driverless
   printer under the same name, so the name check skipped the permanent queue's real URI.
3. **Fallback onto the same link.** P1 got HTTP 503 from ipp-usb; LinPrinter fell back to the (new,
   correct) driverless CUPS queue, which goes through the same ipp-usb link. The 3.9 MB job was cut off
   mid-transfer and left the printer's IPP endpoint hung (`libusb_bulk_transfer: Input/Output Error`)
   until a power cycle.

## Changes
- `backends/usb_link.py` (new): per-port error/disconnect counts from `journalctl -k`; advice text.
- `manager_print.discover`: notes for a printer on a failing port; the remembered printer is listed
  with the reason when it has dropped off; misdirected-queue notes. `status()` keeps a link message.
- `ipp.py`: HTTP 503 -> code `link`; `PrintError.needs_user` includes `link`; `print_async` stops on a
  needs-user error during the status check too.
- `backend_cups.sort_queues`: permanent queues first, `implicitclass://` resolved, `serial:` /
  `parallel:` / `file:` reported as misdirected.
- Printers page and `--list-printers` show notes.

## Verified
79 tests, lint clean. `--list-printers` on the real machine with the printer off the bus:
"Canon TR150 series — not ready — The USB link to this printer keeps failing (14 connection errors
and 1 disconnect on port 3-3 …)". Before: only "Print to PDF".
**Not verified:** the misdirected-queue note live (the user deleted that queue before the fix), and a
complete print on the real printer (the link would not hold).

## Research (2026-10-01): nothing to add
No driver, service, udev rule or dependency is missing. Driverless IPP over ipp-usb is the right path
for the TR150; Canon's cnijfilter2 is not in Debian/Ubuntu/Mint (would break the offline rule);
ipp-usb is started by its own udev rule on every plug-in. ipp-usb 0.9.24's `init-reset` already
defaults to `none` (HOST-USB.md's test #1 rationale needs correcting there).

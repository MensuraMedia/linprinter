# 0.3.0 — The 2026 redesign (Graphite Night) — 2026-10-02

Branch `feat/0.3.0-redesign`; not merged until the user is satisfied.
Design: `docs/design/redesign-2026/` (mockup source, Graphite Night references, intentional departures).

## What changed
- Four destinations (Print, Activity, Printer, Settings) instead of seven; a header status chip.
- UI built on lin-dashboard-theme, vendored as `src/lintheme` (1.2.3). `config_themes.py` and the
  theme applicator are gone; colours come only from `lintheme/tokens.py`.
- New: `pages/page_activity.py`, `pages/page_printer.py`, `ui/app_css.py`, `utils/util_files.py`.
- Rewritten: `pages/page_print.py`, `pages/page_settings.py`, `ui/app_window.py`, `ui/sidebar.py`,
  `ui/content_area.py`.
- Removed: `page_preview.py`, `page_queue.py`, `page_recent.py`, `page_printers.py`, `page_about.py`.
- Managers: `manager_status.chip_key`, `needs_you_words`; `manager_print.ticket_choices`,
  `settings_summary`, `link_test`, `JOB_RESULT_WORDS`; `backend_ipp.ping`;
  `manager_documents.add_recent(result=, choices=)`; preview margins from `PAPER` tokens, dashed guide.
- `features/feature_profiles.py`: themed controls; the row is appended last.
- `app.json` / `install.sh`: `fonts-ubuntu`.
- `tools/walkthrough.py`: 21 screenshots including empty Activity, history, stray queue, fixed.
- Tests: `tests/test_ui_flow.py` (cancelled print in History, Change menu, failed print in Activity).

## Bugs found in review and fixed before release (root causes)
1. Cancelled/aborted jobs were recorded as Printed: `add_recent` after `_follow` passed no result.
2. The Change menu marked the wrong printer: built before `select_printer`, compared by identity.
3. A document opened during a print became the failed print's record: `on_error` read the current
   document, not the job's. Opening documents is now blocked while printing.
4. A status from a previously chosen printer could stick: `last_status` was set outside the guard.
5. Link-test notices vanished on rebuild; the Troubleshooter had no notice; tests could run twice.
6. The Printer page never polled on its own.
7. The Troubleshooter declared "fixed" after a fixed 3.5 s wait, and `key()` read "ok" with no status.
8. A printer that answered with an error (e.g. stopped) showed Can't reach instead of Needs you.
9. Test pages didn't mark the app busy (chip, Activity badge, Print button).
Also: a valid page range kept the error colour; a stale preview render could replace a newer one;
the preview empty text spoke of scanning; stray hex colours outside the tokens; About showed an
absolute personal path.

## Review round 2 (code review + design adversary), fixed
- Test page that fails before starting left the chip and Activity badge on Printing (emit after start).
- Link-test result dropped when a re-search replaced the printer object (compare by id).
- "No connection errors" shown green when the kernel log couldn't be read (`usb_link.log_readable`);
  the log is now read in the status worker and cached 4 s (it ran on the GTK thread).
- Troubleshooter: one give-up timer, cancelled on Close; the Printer page no longer polls twice.
- Paper out during a print shows Needs you; a job still printing at timeout is "Sent (not confirmed)";
  a cancel before submission is "Cancelled"; null dates no longer crash Activity.
- Preview scroll policy NEVER made the window ask for the image's full size (grew to 1057 px):
  EXTERNAL at fit. Thumbnail bar only on overflow. The options column no longer takes spare width
  (a child's hexpand propagated up).
- Activity: the empty state's insides never showed (no_show_all); cancelled is neutral, without Troubleshoot.
- Kit 1.2.4: Hero.lines (the "Checked N s ago" line), em dash in the cable advice.

## Review round 3, fixed
- The kernel log was still read on the GTK thread when the printer had no method or IPP hung past the
  cache age: pages now read only `usb_link.cached()`; `status()` (worker) refreshes after the answer;
  a printer without methods goes through `status_async` too.
- journalctl exits 0 for users outside adm/systemd-journal and omits the kernel's lines: its stderr
  hint now marks the log unreadable ("unknown", never a green all-clear). A USB printer with an
  unreadable log no longer reads "isn't on USB".
- Status is polled during a print too; the chip lets "Needs you" through while printing.
- Last link test shown muted, "(before it stopped answering)", while Can't reach.
- Activity filter "Didn't print" excludes Cancelled and Sent; stale jobs replies can't clear the guard.

## Review round 4, fixed
- Polling during a print (added in round 3) could turn a slow status answer into Can't reach with
  Reconnect under a running job - the 2026-10-01 hang. While printing, everything but Needs you reads
  Busy; the job's own follow reports real failures. Polls run every third tick while printing.
- The chip stuck on Needs you after paper was loaded mid-job; it now returns to Busy.
- A long "Last test" value broke the Printer page's three-card row; the note moved to its own line,
  and the walkthrough now fails if the three cards don't share a row (07, 14).
- journalctl runs with LC_ALL=C (its hints are matched in English); "not read yet" is its own state.

## Review round 5, fixed
- **A pre-existing fallback hole** (found through the new 12b screenshot): if the paper ran out between
  the status check and Print-Job, the printer refused the job (server-error-not-accepting-jobs) and
  LinPrinter tried the next method - the CUPS queue - although the user had to act. Root cause: only
  the status *before* submit was checked. Now a refused submit re-reads status; if the user must act
  it raises "user" (no fallback). Refusals are said in plain words (`refused_words`); the IPP status
  stays in the log.
- Test pages count as printing for the Print page's status (no Reconnect mid-job); status errors
  during a job don't count as misses.

## Review round 6, fixed (design adversary: PASS)
- The round-5 status re-read swallowed a `link` error, so a Print-Job that died with the USB link fell
  back to CUPS on the same link. It now re-raises errors that need the user.
- A cancel during a failing upload is "Cancelled", not a refusal; a printer that isn't taking jobs
  (busy from P1/T) is final - a CUPS queue would only hold the job; CUPS' own words are kept for P2.
- The action bar reads "Waiting for you: …" while a job waits for paper.

## Review round 7, fixed (code review: no blockers left after this)
- Low ink (a warning, mapped to "attention") made a running print look paused: chip, page and bar said
  Needs you / Waiting for you. While printing, only `user_must_act` reasons break through Busy.

## User feedback after the first run (2026-10-02)
- "Make the buttons in Output more uniform": `PrintPage._uniform_row` - every control fills the field
  column (as the Paper selects do) with homogeneous segments; the stepper keeps compact -/+ with a wide
  value; the "up to 99" hint sits under the Copies label (design adversary: a tooltip alone hides it).
  Kit 1.2.5: disabled segments look disabled.
- "Custom page print": it existed as Range; renamed Custom with a clearer example (`2 or 1-3, 5`).
- "No dropdown changed by the mouse wheel": kit 1.2.6 `no_wheel()` on every select (and the Print
  page's size/type combos); the wheel scrolls the page instead. Root cause: GTK 3 ComboBox changes
  its active item on scroll-event by default.
- Design check on that: the departures are listed in docs/design/redesign-2026/README.md; the custom
  box spans the column ("Page list", count under the label); disabled dropdowns/entries look disabled
  (kit 1.2.7); wording "Check the pages to print". A crash (segfault in show_all) came from building a
  throwaway row and re-parenting the stepper out of it: controls are now sized by `_fill`, parented once.
- Re-check: an invalid page list wrote its full error under the label and pushed the box out of line;
  the caption is now "Check it" (the bar has the words). Print is disabled with "Check the pages to
  print" while the list is wrong (it used to complain only after the click). Shot 02d.
- Design check PASS. Minors applied: the reason beside Print is "Fix the page list first" (the bar's
  headline says what to check); while the list is wrong the preview says "Nothing to show: fix the
  page list." (`PagePreview.show_message`, kept across redraws) instead of the last valid pages.

# 0.2.5 Reconnect, 0.2.6 IPP robustness, 0.2.7 licence — 2026-09-24

## 0.2.5 — Reconnect
The recovery command from the TR150 trouble, built into the app: a button beside **Find** when the
mark is red, one per printer on the Printers page, and `run.sh --reconnect`.
- `src/backends/usb_reset.py` re-attaches **one** device: it follows the printer by USB id, refuses a
  port that now holds something else or is not a printer, and waits for it to come back configured.
- Privilege comes from pkexec (the desktop's own dialog) running
  `/usr/local/lib/linprinter/linprinter-usb-reset`, installed by `install.sh` and the `.deb` with its
  polkit action. Nothing is left running.
- **No udev rule is installed, deliberately** — granting a user permanent control of a device's USB
  attachment is the machine administrator's decision. The 0.2.5 docstring wrongly claimed one;
  corrected in 0.2.6.
- The printer's USB identity (id + port) is stored with the remembered printer, so it survives a
  restart and follows the printer to another socket.
- **Verified against the real TR150**: polkit prompt, only port 3-4 touched, "connected again",
  exit 0. It has cleared the printer's hung IPP endpoint every time.

## 0.2.6 — robustness, found because the hardware misbehaved
- **A cut-short IPP answer is reported, not crashed.** The USB link dropped a 119 KB reply
  mid-message (`libusb_bulk_transfer: Input/Output Error`); the decoder read a length field that
  wasn't there and raised `struct.error`, which nothing catches, so a status check took the app down.
  Every length and value is bounds-checked now, **and a reply without its end-of-attributes tag is
  refused** — previously such a fragment came back looking whole, so a half-read printer appeared to
  have no paper sizes.
- **Graceful degradation**: the full request is tried first (Canon answers a *named*
  `media-col-database` more fully than a plain "all"), and a cut-short reply falls back to the
  essentials, then asks for the big extra alone. Losing the extra costs only borderless combinations.
- **Alternate settings** are read from the raw `descriptors` blob, because the TR150 keeps
  IPP-over-USB (7/1/4) on alternate setting 1 of interfaces 1 and 2 while setting 0 is
  vendor-specific, and sysfs shows only the current setting. Before this the app called it a plain
  USB printer and told the user to add a CUPS queue.
- The unusable-printer hint depends on whether ipp-usb is installed; `--list-printers` no longer
  hides a connected printer with no working method.
